# zabbix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A kiosk page `zabbix/index.html` that polls the Zabbix 6.0 JSON-RPC API and shows a host tile grid (coloured by worst open problem) and a problem list on one 1920×1080 screen, with a connection-failed / stale banner, reproducing `../pi-setup/ansible/roles/zabbix-display`.

**Architecture:** Copy of `_template/index.html` (kiosk shell: toolbar with fullscreen, settings modal, status bar, next-refresh timer). `Logic` holds URL/list parsing, JSON-RPC request/response helpers, data merge (hosts × problems × triggers) and all layout arithmetic (tile grid, font fitting from pre-measured widths, visible rows, stale age). `App` runs the 4-call refresh pipeline, measures text with a hidden canvas, and renders two panes plus a banner.

**Tech Stack:** Vanilla HTML/CSS/JS, `node:test`, fixtures under `zabbix/test/fixtures/`.

**Spec:** `docs/superpowers/specs/2026-11-04-zabbix-design.md` (authority). Conventions: `docs/conventions.md` (sections 2 and 3.1), `CLAUDE.md`. Reference implementation to mirror: `/Users/yt/git/pi-setup/ansible/roles/zabbix-display/templates/zabbix-display.py.j2` (read-only; copy its rules, not its code).

## Global Constraints

- One page `zabbix/index.html`, no external resources; only `Logic`/`App` globals; no `innerHTML`; `textContent`; no emoji; no bold (`font-weight` ≥ 600, `<b>`, `<strong>`); Material Icons inline `<symbol>`s.
- Colours (exact, from the spec table): bg `#14181e`, pane `#1e242c`, fg `#f0f0f0`, fg-dim `#aaaaaa`, sev-0..5 `#97aab3 #7499ff #ffc859 #ffa059 #e97659 #e45959`, ok `#5cb85c`, disabled `#505050`, error band `#6e1414`, stale band `#6e4600`. Tile and problem-row text colour on a severity colour is black.
- Settings keys (exact): `zabbixUrl` string `''`; `token` string `''`; `hostGroups` string `''`; `hosts` string `''`; `severityMin` int 0–5 default 2; `refreshSec` int 15–600 default 60; `requestTimeoutSec` int 3–60 default 10; `staleSec` int 30–3600 default 150; `problemMaxRows` int 1–50 default 20; `tileMinChars` int 4–30 default 10; `tileMinFont` int 10–40 default 16; plus `lang`/`theme`/`zoom`. `DISPLAY_ONLY_KEYS` = `theme zoom lang staleSec problemMaxRows tileMinChars tileMinFont`. The template's `refreshMinutes` is removed.
- JSON-RPC: `POST`, `Content-Type: application/json`, body `{ jsonrpc: '2.0', id, method, params, auth }` where `auth` is the token (or `null` when empty); `cache: 'no-store'`; `AbortSignal.timeout(requestTimeoutSec * 1000)`. No `Authorization` header.
- Layout rules (from the role; `floor` = integer division): pane margin 14; `cols = max(1, min(n, 8, round(sqrt(n * aspect))))` with `aspect = availW / max(availH, 1)`; `rows = ceil(n / cols)`; `tileW = floor((availW - 14*(cols-1)) / cols)`; `tileH = floor((availH - 14*(rows-1)) / rows)`; if `tileH < 40`: `rows = max(1, floor((availH + 14) / 54))`, recompute `tileH`, `visible = min(n, cols*rows)`, `truncated = visible < n`, and when truncated `tileH = max(40, tileH - floor(30 / rows))`. Font: `nameSize = min(64, floor(tileH * 0.40))`, then for heads (scale 1) and tails (scale 0.7) `limit = floor(100 * textBox / widest100 / scale)` with `textBox = tileW - 12` and `widest100` = widest sample width measured at 100px; `nameSize = max(tileMinFont, min(nameSize, limits…))`; `subSize = max(12, floor(nameSize * 0.7))`; `lineGap = max(2, floor(nameSize / 8))`. Problem rows: `rowH = 50`, severity bar width 140, pad 12, `rowsFit = max(1, floor((paneH - 24 - 30) / 50))`, `visible = min(count, problemMaxRows, rowsFit)`.
- Tests: `node --test zabbix/test/*.test.mjs` (glob form). No network in tests. `process.env.TZ = 'Asia/Tokyo'` where `Date` is involved.
- Commit footer: `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. A problem whose trigger spans an in-scope and an out-of-scope host must count for the in-scope host and show that host's name; a problem whose trigger has only out-of-scope hosts must be dropped (Task 2 `mergeData` tests).
2. Disabled hosts (`status: "1"`) show the disabled colour even with open problems, and count as BAD in the footer (Task 2).
3. 200 hosts: the grid truncates with `+ N more (out of M)` and never overflows the pane (Task 3 `tileLayout` test, Task 4 CSS).
4. The API returning `{ error }` (bad token, bad method) must show the red banner with `error.data`, keep the previous tiles, and keep polling (Task 4).
5. Settings change of a display-only key must re-render without refetching; a connection key change must refetch immediately (Task 1 `DISPLAY_ONLY_KEYS`, Task 4).
