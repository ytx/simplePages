前提: 共通規約 `2026-10-12-simplepages-conventions-design.md`、`2026-10-13-toolbar-and-settings-modal-design.md`。設定モーダル・ツールバー・i18n・テーマ・拡縮・データタブは規約どおりで、本書では差分だけ書く。

## 目的

面会(1 対 1 の打合せ)の日程調整を一人で回すための手元ツール。

依頼者(以下クライアント)から面会の依頼が来たとき、または自分から持ちかけるとき、自分の「面会可能な時間帯」から候補を数件選び、メールや LINE に貼れる文面を作る。提示した候補は回答が来るまで**仮押さえ**し、別のクライアントに重ねて提示しない。回答が来たら 1 件を確定し、残りを解放する。

いまは紙の手帳と Google カレンダーを併用しており、仮押さえの管理(どの枠を誰にいつまで提示したか)が一番の手間になっている。本ページはそこを肩代わりする。

利用環境は主にスマートフォンのブラウザ。データはすべて localStorage に置き、サーバーへは何も送らない。Google カレンダー等との連携はしない。

## 用語

| 用語 | 意味 |
|---|---|
| 可能帯(band) | 「この時間帯なら面会できる」という帯。日付と開始・終了時刻を持つ。週ごとに手で置く。繰り返しルールは持たない |
| 予定(block) | 可能帯の中(または外)で面会に使えない時間。ランチや別件。`kind: 'busy'` |
| 面会(meeting) | 確定した面会。`kind: 'meeting'` の block で、クライアントに紐付く |
| スロット | 可能帯を「スロット長 + インターバル」で切った、提示の単位となる枠 |
| 提示(proposal) | 1 クライアントに対し、複数スロットと回答期限を添えて送った候補の束 |
| 仮押さえ | 回答待ち(`pending`)の提示に含まれるスロット。空き枠から除外される |
| 回答期限 | 提示に添える日付。過ぎても**自動では何も起こさない**(解放しない) |

## 画面構成

4 つのタブを画面下部に置き、アイコンとラベルで切り替える。上部には共通ツールバー、タブバーの直上に共通のステータス帯(短縮形)を置く。

```
┌───────────────────────────────[◐][−][+][⛶][A][⚙]┐ header#toolbar
│ time4u                                          │ h1#page-title(小さく)
│                                                 │
│   (タブの内容)                                   │ main > section.tab-pane × 4
│                                                 │
├─────────────────────────────────────────────────┤
│ 12:34  ● 保存済み                                │ footer#status(1 行)
├───────────┬───────────┬───────────┬─────────────┤
│ [person]  │ [week]    │ [month]   │ [settings]  │ nav#tabbar(アイコン + ラベル)
│ クライアント│ 週        │ 月        │ 設定         │
└───────────┴───────────┴───────────┴─────────────┘
```

- タブ: `clients` / `week` / `month` / `settings`。初期は `clients`。タブのアイコンは Material Icons の `person`、`calendar_view_week`、`calendar_month`、`settings` をインライン SVG(`<symbol>` + `<use>`)で埋め込む。
- **絵文字は UI に使わない**(ボタン、見出し、ラベル、ステータス、ダイアログすべて)。アイコンが必要な箇所は Material Icons(Google Fonts、Apache 2.0)のパスをインライン SVG で埋め込む。ユーザーが編集する文面(ヘッダ・フッタ・リマインド)に絵文字が入るのは構わない。URL クエリ `tab=` で開くタブを指定できる(保存はしない)。
- 設定タブは共通の設定モーダルを開くだけのショートカットではなく、モーダルと同じ内容をタブ内に埋め込んで表示する(スマホでモーダルの固定サイズが収まりにくいため)。ツールバーの ⚙ は設定タブへ切り替える。モーダルのタブ構成(一般 / 表示 / 文面 / 時間 / データ / About)をそのままタブ内の縦並びセクション(折り畳み)にする。
- ステータス帯は現在時刻と保存状態(緑: 保存済み、黄: localStorage が使えずメモリ上だけで動作中)。最終更新時刻・取得状態は表示しない(取得がないため)。`refresh()` は何もしない。
- ページ固有のツールバーボタンはない。
- 画面内の遷移(クライアント → 空き枠 → 文面、週 → 1 日)は `main` 内の子ビューを横スライドで切り替える。各子ビューの左上に「‹ 戻る」。ブラウザの戻るボタンとは連動しない(`history` は触らない)。

### 構成

```
time4u/
  index.html                       ページ本体
  fonts/zen-kurenaido/zk-000.woff2 … zk-123.woff2   書体(124 ファイル、合計約 2.1 MB)
  fonts/zen-kurenaido/OFL.txt      SIL Open Font License 1.1
  test/                            Logic のテスト
  README.md
```

### 書体

- 全体に **Zen Kurenaido**(ペン字。SIL OFL 1.1)。`../green`(`packages/client/public/fonts/zen-kurenaido/`、`src/styles/fonts.css`)が自前配信している Google Fonts のサブセット分割 124 本をそのままコピーし、`fonts.css` の 124 個の `@font-face` を index.html の `<style>` に埋め込む。`url()` は `fonts/zen-kurenaido/zk-NNN.woff2` の相対パス、`font-display: swap`。unicode-range による分割なので、実際に読み込まれるのは画面に出た文字の分だけ。
- フォールバックは共通のシステムフォントスタック。`--font: 'Zen Kurenaido', system-ui, -apple-system, "Segoe UI", Roboto, "Hiragino Sans", "Noto Sans JP", sans-serif`。
- weight は 400 しかないので **太字は使わない**。強調は文字サイズと色で付ける。数字は `font-variant-numeric: tabular-nums`。
- これは共通規約「Web フォントは使わない」の例外。音声・画像と同じく「同じページディレクトリ内のメディアを相対パスで読み込む」例外に書体ファイルを加える形で `CLAUDE.md` と共通規約の該当行を更新する(外部ドメイン・CDN は引き続き禁止)。About のクレジットに Zen Kurenaido(SIL OFL)を載せる。

### 見た目

「柔らかい」印象を狙う。ペン字の書体に合わせ、ライト・ダークで同じ系統の色を使う。

- 状態色は彩度を落とした 4 色。可能帯 = 緑、仮押さえ = 黄、面会(確定) = 青、予定 = グレー。ライトでは淡い塗り + 濃い文字、ダークでは暗い塗り + 淡い文字。`--c-avail`、`--c-hold`、`--c-meeting`、`--c-busy` と、それぞれの `-text` を `:root` に置く。
- 角丸は大きめ(`--radius: calc(12px * var(--zoom))`)、影は薄く 1 段。
- 文字サイズは `--fs-base` を 16px 相当にし、タップ対象は最小 44px 角。
- `prefers-reduced-motion: reduce` ではスライド遷移を即時切替にする。

## クライアントタブ(`#tab-clients`)

### 一覧

```
┌ [ たな|                              ] ┐  検索・新規登録欄
│ ＋「たな」で新規登録                     │  一致なし/完全一致なしのときだけ表示
├ ▸ 確定済み (2)                          ┤  初期は折り畳み
├ ▾ 調整中 (3)                           ┤  初期は開いている
│  田中さん  3 件提示 · 期限 10/22  [取消] │
│  鈴木さん  期限切れ 10/18        [取消] │  赤系の印
├ ▾ 過去の面会            最終面会の降順 ┤
│  棚橋さん  最終 9/30     [新しく提示]   │
└────────────────────────────────────────┘
```

- **敬称**: 画面上の名前は `name + 設定 honorific`(既定「さん」)で表示する(「田中さん」)。保存する `name` には敬称を含めない。
- **検索・新規登録欄**: 1 つの `<input>`。入力のたび(`input` イベント。IME 変換途中でも発火する)に 3 セクションの行を絞り込む。一致判定は `Logic.matchesClient(client, query)`: `query` と、クライアントの `name`・`reading` を `Logic.normalizeKana` で正規化(全角→半角英数、カタカナ→ひらがな、空白除去、小文字化)したうえで部分一致。
  - **読みの自動取得**: 変換中に `compositionupdate` で届く文字列を保持し、確定(`compositionend`)後も「この入力欄で最後に打った読み」として残す。新規登録時にその読みを `reading` に保存する。読みは行の長押し → 編集シートで直せる。これにより「たな」で「田中」が引ける。
  - **クライアント編集シート**(行の長押し、または行末の ⋯ から): 名前と読みの編集、削除。削除はそのクライアントが `pending` の提示も今後の面会も持たないときだけ有効(持っていればボタンを無効にし「調整中の提示 / 今後の面会を先に取り消してください」と表示)。削除すると過去の面会(block)と過去の提示も一緒に消す。
  - 欄が空なら全件表示。1 文字以上で、`name` が完全一致する行がなければ欄の直下に「＋『(入力文字)』で新規登録」ボタンを出す。押すと `addClient(name, reading)` して、そのクライアントで空き枠画面へ進む。
- **セクション**(見出しタップで開閉。開閉状態は保存しない):
  1. **確定済み**: 今後の面会(`kind:'meeting'` で終了時刻が現在以降)を 1 件 1 行。表示は「名前 · 10/22(木) 13:00–14:30」。行のボタンは **[リマインド]**(リマインド文面画面へ)と **[取消]**(ダイアログで確認 → block を削除)。行タップで次の面会を重ねて提示できる(「新しく提示」と同じ動作で空き枠画面へ)。初期は折り畳み。
  2. **調整中**: `status:'pending'` の提示を 1 件 1 行。「名前 · N 件提示 · 期限 10/22」。期限を過ぎた(本日の日付 > 期限)行は `.expired` を付け「期限切れ 10/18」と赤系で表示するが、仮押さえはそのまま。行のボタンは **[取消]**(ダイアログで確認 → `status:'cancelled'`。仮押さえ解放)。行タップで回答反映画面へ。初期は開いている。
  3. **過去の面会**: 過去の面会(終了時刻が現在より前)を 1 件以上持つクライアントを、最終面会日の降順に 1 人 1 行。「名前 · 最終 9/30」。行のボタンは **[新しく提示]**。
  - どのセクションにも載らないクライアント(登録したが提示を取消しただけ、など)は検索欄に文字があるときだけ「その他」セクションとして表示する。
- 同じクライアントが複数セクションに出てよい(確定済みの相手に次の提示をしている状態など)。

### 空き枠画面(`#view-slots`)

クライアントを決めたあとの画面。

```
┌ ‹ 戻る     田中さん ───────────────────────┐
│ ┌ 条件 ─────────────────────────────── ▸ ┐│  カード。タップで条件モーダル
│ │ 10/20〜11/2 · 月火木金 · 午前 午後 · 90 分 ││
│ └───────────────────────────────────────┘│
│ [おまかせで 3 件]  [解除]                  │
│ 10/20(火)                                 │
│  ☑ 13:00 – 14:30                          │
│  ☐ 14:40 – 16:10                          │
│ 10/22(木)                                 │
│  ☐ 9:00 – 10:30                           │
│  …                                        │
│ ┌───────────────────────────────────────┐│
│ │        3 件で文面を作る →              ││  下部固定。0 件なら無効
│ └───────────────────────────────────────┘│
```

- **条件カード**: 期間・曜日・時間帯・スロット長を 1 行に要約。タップで**条件モーダル**(ページ内ダイアログ)を開き、4 項目をまとめて編集して「適用」。
  - 期間: 開始日・終了日(`<input type="date">`)。既定は本日 + 設定 `rangeStartDays` 日から、そこから設定 `rangeDays` 日間。
  - 曜日: 月〜日のトグル。既定は月〜金。
  - 時間帯: 午前(開始 < `pmStart`)/ 午後(`pmStart` ≤ 開始 < `eveStart`)/ 夜(開始 ≥ `eveStart`)のトグル。既定は午前・午後。境界は設定(既定 12 時・17 時)。
  - スロット長: 設定 `slots` の値からラジオ。既定は設定 `defaultSlot`。
  - 条件はこの提示の間だけ保持し、「再提示」のときは元の提示の条件を初期値にする。設定には保存しない。
- **一覧**: `Logic.freeSlots(data, conditions, settings, now, excludeProposalId)` の結果を日付ごとに見出し付きで並べる。仮押さえ中の枠(自分のクライアント宛てのものも含む)、予定・面会と重なる枠、開始が現在時刻より前の枠は**一覧に出さない**。例外は「再提示」で、元の提示の ID を `excludeProposalId` に渡し、その仮押さえだけは空きとして扱う(前回出した枠を選び直せる)。チェックボックス風の行。タップで選択トグル。
- 1 クライアントが `pending` の提示を同時に複数持つことは禁止しない(確定済みの相手に次の提示を重ねるのと同じ扱い)。
- **インターバルの置き方**: インターバルは「面会と面会の間に空ける時間」であり、面会(`meeting`)と仮押さえの前後にだけ空ける。可能帯の端と予定(`busy`。ランチなど、それ自体が休み)の前後には空けない。空き区間の切り方は次のとおり。
  1. 可能帯から面会・仮押さえ・予定を引いて空き区間を作る。
  2. 空き区間の始まりが面会・仮押さえの終わりに接していれば `interval` 分だけ後ろへ、終わりが面会・仮押さえの始まりに接していれば `interval` 分だけ前へ縮める。
  3. 縮めた区間の始まりから `slotMin + interval` 刻みで、終わりが区間内に収まる枠を列挙する。
  - 例: 帯 13:00–17:00、90 分、インターバル 10 → 13:00–14:30、14:40–16:10。13:00–14:30 を仮押さえすると残りは 14:40–16:10 の 1 枠(位置は変わらない)。帯 10:00–15:00 にランチ 12:00–13:00 → 10:00–11:30、13:00–14:30。
- **おまかせで N 件**: `Logic.pickSpread(slots, selected, n)` で、現在の選択を残したまま合計 `n`(設定 `pickCount`、既定 3)になるまで追加する。選択を外してもう一度押せば、外した分だけ別の枠で補われる。**解除**は選択を空にする。
- **文面を作る →**: 選択 1 件以上で有効。文面画面へ。

### 文面画面(`#view-message`)

```
┌ ‹ 戻る     田中さん ───────────────────────┐
│ 回答期限  [ 2026-10-22 ]   (初期値: 3 日後) │
│ ┌───────────────────────────────────────┐│
│ │ お世話になっております。               ││  textarea。自由編集可
│ │ 面会の候補日時をお送りします。         ││
│ │ …                                     ││
│ │ ・10月20日(火) 13:00〜14:30           ││
│ │ ・10月22日(木) 10:40〜12:10           ││
│ │ …                                     ││
│ │ 恐れ入りますが 10月22日(木) までに …   ││
│ └───────────────────────────────────────┘│
│ [ コピーして仮押さえ ]                     │
```

- 回答期限: `<input type="date">`。初期値は本日 + 設定 `deadlineDays`。変更すると文面の `{期限}` 部分を再生成する(ただしユーザーが textarea を手で編集したあとは、期限変更時に「文面を作り直しますか」とダイアログで確認し、OK なら再生成、キャンセルなら期限の値だけ変える)。
- 文面は `Logic.buildMessage(template, slots, deadline, lang)` で生成: ヘッダ + 空行 + 日程(1 行 1 件、`・` 付き)+ 空行 + フッタ。`{期限}` を `Logic.formatDateLong(deadline, lang)`(例 `10月22日(木)` / `Thu, Oct 22`)で置換する。それ以外の差し込みはない。
- **コピーして仮押さえ**: `navigator.clipboard.writeText` を試み、失敗したら textarea を全選択して `document.execCommand('copy')`。どちらも失敗したら文面はそのまま残し、ステータス帯に「コピーできませんでした。長押しで選択してください」(黄)。**クリップボードの成否にかかわらず**提示を保存する(`status:'pending'`、スロット・期限・最終文面・条件を保持)。成功時はボタンを 2 秒間「コピーしました ✓」にしてからクライアント一覧へ戻る。
- 「再提示」から来た場合、ここで保存した時点で元の提示を `cancelled` にする(仮押さえを引き継がず、新しい提示の分だけ押さえる)。

### 回答反映画面(`#view-respond`)

調整中の行をタップして開く。

```
┌ ‹ 戻る     田中さん   回答待ち ─────────────┐
│ 提示した日程   期限 10/22(木) · 残り 2 日   │   期限切れなら「期限切れ · 3 日経過」(赤系)
│  ○ 10/20(火) 13:00 – 14:30                │
│  ● 10/22(木) 10:40 – 12:10                │   ラジオ
│  ○ 10/27(火) 13:00 – 14:30                │
│ [ この日程で確定 ]                          │   選択時のみ有効
│ [文面を再表示] [期限を延ばす]                │
│ [取消(全て解放)]                            │
```

- **確定**: 選んだスロットで `kind:'meeting'` の block(`clientId`、`proposalId`)を作り、提示を `status:'confirmed'`、`confirmedSlot` を記録。他のスロットは提示が pending でなくなることで自然に解放される。確定後は確定済みセクションに移る。
- **文面を再表示**: 保存した最終文面を読み取り専用で表示し、コピーボタンを付ける(送り直し用)。
- **期限を延ばす**: `<input type="date">` のダイアログ。保存した文面は変えない。
- **取消**: ダイアログで確認 → `cancelled`。
- **再提示**(期限切れの行にだけ追加で表示): 元の条件で空き枠画面へ。

### リマインド文面画面(`#view-reminder`)

確定済みの行の [リマインド] から開く。設定 `templates.reminder` の `{日時}` を `Logic.formatSlotLong(slot, lang)`(例 `10月22日(木) 13:00〜14:30`)で置換した文面を textarea に出し、[コピー] ボタンを置く。保存はしない。

## 週タブ(`#tab-week`)

```
┌ ‹  10/19 – 10/25  ›            [複写] ┐
│    月  火  水  木  金  土  日           │
│ 9  ▒▒  ▒▒      ▒▒  ▒▒                 │  7 列。帯は色のみ、文字なし
│ 12 ▒▒  ▓▓      ▓▓  ▒▒                 │
│ 15 ▒▒  ▒▒          ▒▒                 │
│ 18                                     │
└────────────────────────────────────────┘
```

- 週の始まりは設定 `weekStart`(既定: 月曜)。左右の矢印と横スワイプ(calendar ページと同じ角度判定: `|dx| ≥ 60 && |dx| ≥ 1.5·|dy|`、pointerup は `window` で拾う)で前後の週へ。見出しタップで今週へ。
- 縦軸は設定 `dayStart`〜`dayEnd`(既定 8〜21 時)。その範囲外に帯や予定があれば、その週だけ軸を伸ばして全部見せる。
- 各列に可能帯(緑)、その上に予定(グレー)・面会(青)・仮押さえ(黄)を重ねる。文字は入れない。本日の列に印、現在時刻に細線。
- **列をタップ**すると、その日の **1 日ビュー**(`#view-day`)が右からスライドして開く。
- **複写**: ダイアログで、可能帯を 1 つ以上持つ過去 8 週(新しい順。「10/12 週 · 可能帯 5 本」のように表示)から 1 週を選ぶ。選んだ週の可能帯だけを、曜日を揃えて今の週に写す(`Logic.copyWeekBands(data, fromWeekStart, toWeekStart)`)。予定・面会・仮押さえは写さない。今の週にすでに可能帯があるときは「置き換える / 追加する / キャンセル」を聞く。

### 1 日ビュー(`#view-day`)

```
┌ ‹ 10/20(火) ›                        ✕ ┐
│ 9:00  ┃▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒ │  可能帯(帯の中にアイテムを重ねる)
│ 12:00 ┃▒▒▒▒ ランチ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒ │
│ 13:00 ┃▒▒▒▒ 田中さん(仮) 〜10/22 ▒▒▒▒▒▒▒ │
│ 15:00 ┃▒▒▒▒ 佐藤さん 確定 ▒▒▒▒▒▒▒▒▒▒▒▒▒▒ │
│ 18:00 ┃                                 │
│                                   [＋]  │
```

- 左右矢印・横スワイプで前後の日。✕ で週へ戻る。
- アイテムは幅いっぱいで文字入り。仮押さえには「名前(仮) 〜期限」、面会には「名前 確定」、予定にはタイトル。
- **＋** または空き時間のタップで**アイテム編集シート**を開く。既存アイテムのタップでも同じシートを開く(仮押さえは編集不可。タップすると回答反映画面へ)。
- **アイテム編集シート**(ページ内ダイアログ):
  - 種類: 可能帯 / 予定 / 面会 のセグメント。
  - 開始・終了: 10 分刻みの `<select>` 2 つ(`<input type="time">` は OS により刻みを無視するため)。空き時間タップから開いたときは、タップ位置を 10 分に丸めた時刻を開始、+ 設定 `defaultSlot` 分を終了にする。
  - 予定: タイトル(任意)。面会: クライアント(既存から選択、または新規名入力)。
  - [保存] [削除](既存のみ)[キャンセル]。終了 ≤ 開始 は保存不可。可能帯どうしが重なる保存は、重なった帯を結合して 1 本にする(`Logic.mergeBands`)。
- ドラッグでの伸縮・移動は入れない(範囲外)。シートの時刻選択だけで編集する。

## 月タブ(`#tab-month`)

- `‹ 2026 年 10 月 ›`、曜日見出し(設定 `weekStart` に従う)、6 行 × 7 列。
- 各日: 日付の数字。可能帯のある日は薄い緑の背景。下に小さな点を最大 3 つ: 面会(青)の数、仮押さえ(黄)の数を点で表す(4 つ以上は `+`)。
- 日をタップすると週タブへ切り替え、その日を含む週を表示する。それ以外の編集はしない(View のみ)。

## 設定(`#tab-settings`)

localStorage キー `simplePages.time4u`、`version: 1`。全キーが表示だけに影響する(`DISPLAY_ONLY_KEYS` に全キーを入れ、`refresh()` は no-op)。設定変更時は現在のタブを再描画する。

| セクション | キー | 型 | 既定 | 説明 |
|---|---|---|---|---|
| 一般 | `lang` | `'ja' \| 'en'` | 言語検出 | 共通 |
| 一般 | `honorific` | 文字列(0〜10 文字) | ja: `さん`、en: 空 | 名前の後ろに付ける敬称。空も可 |
| 表示 | `theme` | `'light' \| 'dark'` | OS | 共通 |
| 表示 | `zoom` | 50〜200 | 100 | 共通 |
| 表示 | `weekStart` | 0 \| 1 | 1(月曜) | 週・月の始まりの曜日 |
| 表示 | `dayStart` | 0〜23 | 8 | 週・日ビューの軸の開始時 |
| 表示 | `dayEnd` | 1〜24 | 21 | 同終了時。`dayStart` 以下なら既定に戻す |
| 時間 | `slots` | 整数配列(各 10〜480) | `[60, 90, 120]` | 選べるスロット長(分)。1〜6 個。昇順に正規化 |
| 時間 | `defaultSlot` | 整数 | 90 | `slots` に含まれない値なら先頭に補正 |
| 時間 | `interval` | 0〜120 | 10 | スロット間のインターバル(分) |
| 時間 | `deadlineDays` | 0〜30 | 3 | 回答期限の既定(日後) |
| 時間 | `pickCount` | 1〜10 | 3 | 「おまかせ」の件数 |
| 時間 | `rangeStartDays` | 0〜60 | 1 | 条件の既定期間の開始(本日から何日後) |
| 時間 | `rangeDays` | 1〜90 | 21 | 条件の既定期間の長さ(日) |
| 時間 | `pmStart` | 1〜23 | 12 | 「午後」の開始時 |
| 時間 | `eveStart` | 2〜24 | 17 | 「夜」の開始時。`pmStart` 以下なら既定に戻す |
| 文面 | `templates.header` | 文字列 | ビジネス文例 | 提示ヘッダ |
| 文面 | `templates.footer` | 文字列 | ビジネス文例 | 提示フッタ。`{期限}` を差し込む |
| 文面 | `templates.reminder` | 文字列 | ビジネス文例 | リマインド。`{日時}` を差し込む |

- 文面セクションには 3 つの textarea と、「文例を読み込む: [ビジネス] [フレンドリー]」ボタン。押すとダイアログで確認して 3 つを現在言語の文例で上書きする。初回起動時の既定はビジネス文例(現在言語)。差し込み記法は言語に関係なく `{期限}` と `{日時}`(英語の文例にも同じ記法を使う。表示ラベルで説明する)。
- 文例(ja、ビジネス):
  - header: `お世話になっております。\n面会の候補日時をお送りします。\nご都合のよい日時をお知らせください。`
  - footer: `恐れ入りますが {期限} までにご返信いただけますと幸いです。\nいずれも難しい場合は別途ご相談ください。`
  - reminder: `お世話になっております。\n{日時} の面会について、改めてご連絡いたします。\n当日はよろしくお願いいたします。`
- 文例(ja、フレンドリー):
  - header: `こんにちは!\n面会の候補日をいくつか挙げてみました。\n都合のいい日時を教えてください。`
  - footer: `{期限} までに返事をもらえると助かります。\nどれも難しければ、また相談しましょう。`
  - reminder: `こんにちは!\n{日時} の面会、楽しみにしています。\nよろしくお願いします。`
- 英語の文例は上を自然な英語にしたもの(ビジネス・フレンドリー各 3 本)。実装者が書く。
- `slots` は設定 UI では「60, 90, 120」のようなカンマ区切りテキストで編集し、`Logic.parseSlotList` で正規化する。
- データセクション(共通の「データ」タブ相当)のエクスポートは `{ version, settings, data }` を 1 つの JSON にする。インポートは `settings` と `data` のどちらか/両方を受け付け、含まれていた方を**丸ごと置き換える**(足し合わせない。端末間の移行が用途のため)。置き換え前にダイアログで確認する。全消去は設定とデータの両方を消す。

## データ(`simplePages.time4u.data`)

```js
{
  version: 1,
  clients:   [ { id, name, reading, createdAt } ],
  bands:     [ { id, date: 'YYYY-MM-DD', start: 'HH:MM', end: 'HH:MM' } ],
  blocks:    [ { id, date, start, end, kind: 'busy' | 'meeting', title, clientId, proposalId } ],
  proposals: [ { id, clientId, status: 'pending' | 'confirmed' | 'cancelled',
                 slots: [ { date, start, end } ], deadline: 'YYYY-MM-DD',
                 message, conditions: { from, to, weekdays: [0..6], timeOfDay: ['am','pm','eve'], slotMin },
                 createdAt, confirmedSlot, confirmedAt, cancelledAt } ]
}
```

- `id` は `prefix_` + `Date.now()` + 乱数 4 桁(`c_` `b_` `k_` `p_`)。
- 日付・時刻はローカルの文字列。`Date` を使う計算は `Logic.addDays(dateStr, n)`(正午基準で DST を避ける)と `Logic.weekStartOf(dateStr, weekStart)` だけに閉じる。「現在」は App が `now`(`Date`)として渡す。
- 読み込み時に `Logic.normalizeData(raw)` で形を正す(未知のキーは捨てる、配列でないものは空配列、参照先のないクライアント ID を持つ block/proposal は捨てる、`status` が不正なら `cancelled`)。壊れた保存データでも落ちない。
- 変更のたびに保存する。localStorage が使えないときはメモリ上だけで動き、ステータス帯を黄にする。

## Logic(純粋関数、テスト対象)

| 関数 | 役割 |
|---|---|
| `normalizeKana(s)` | 全角英数→半角、カタカナ→ひらがな、空白除去、小文字化 |
| `matchesClient(client, query)` | `name` または `reading` の正規化後の部分一致。`query` が空なら true |
| `clientSections(data, now)` | `{ confirmed: [{ client, block }], pending: [{ client, proposal, expired }], past: [{ client, lastDate }], other: [client] }` |
| `holds(data)` | pending 提示のスロット一覧(仮押さえ) |
| `freeIntervals(data, date, interval, excludeProposalId)` | その日の可能帯 − 予定 − 面会 − 仮押さえ(`excludeProposalId` の分は除かない)の区間列。面会・仮押さえに接する側を `interval` 分縮める |
| `freeSlots(data, conditions, settings, now, excludeProposalId)` | 期間内・曜日・時間帯で絞り、各区間を `slotMin + interval` 刻みで切る。開始が `now` 以前の枠は除く。日付順・時刻順 |
| `timeOfDay(start, settings)` | `'am' \| 'pm' \| 'eve'`(`pmStart` / `eveStart` で判定) |
| `displayName(client, settings)` | `name + honorific` |
| `pickSpread(slots, selected, n)` | 選択を保ったまま `n` 件まで追加。追加は「選択済みと日付が最も離れている」→「時間帯が被らない」→「早い順」で決める |
| `buildMessage(templates, slots, deadline, lang)` | 提示文面 |
| `buildReminder(templates, slot, lang)` | リマインド文面 |
| `formatDateLong(date, lang)` `formatSlotLong(slot, lang)` `formatRange(start, end)` | 書式 |
| `isExpired(proposal, today)` | `today > deadline` |
| `daysUntil(deadline, today)` | 残り日数(負なら経過) |
| `addDays`, `weekStartOf`, `weekDates(weekStart)` | 日付計算 |
| `mergeBands(bands)` | 同日で重なる・接する可能帯を結合 |
| `copyWeekBands(data, from, to, mode)` | `mode: 'replace' \| 'add'`。曜日を揃えて複写し、結合する |
| `itemsForDay(data, date)` / `itemsForWeek(data, weekStart)` | 描画用の帯・予定・面会・仮押さえの一覧(色種別付き) |
| `monthCells(data, year, month, weekStart, now)` | 月タブの 42 セル |
| `parseSlotList(text)` | `"60, 90,120"` → `[60, 90, 120]`。不正は既定 |
| `normalizeData(raw)` | 上記 |
| `defaultTemplates(lang, style)` | 文例 |
| 共通: `I18N`, `t`, `resolveSettings`, `migrateStored`, `parseImport` | ひな形どおり |

## App(DOM)

- タブ切替、子ビューのスライド、ダイアログ(条件モーダル、アイテム編集シート、確認・日付入力)、localStorage 保存、クリップボード、`compositionupdate` の読み取り。
- 1 分ごとに「現在」を更新し、ステータス帯の時刻、週・日ビューの現在線、期限切れ判定(表示だけ)を再描画する。
- 週・日ビューの縦位置は `(分 − dayStart×60) / ((dayEnd − dayStart)×60)` の割合で `top`/`height` を % 指定する。

## エラー処理

- localStorage 不可: メモリ動作 + ステータス黄 + 保存時にトースト「保存できません」。
- クリップボード不可: 文面を残して黄のメッセージ。提示は保存する。
- 不正な保存データ: `normalizeData` で捨てる。設定は `resolveSettings` が既定に戻す。
- 空の可能帯で「空き枠を見る」: 一覧に「この期間に空き枠がありません。週タブで面会可能な時間帯を登録してください」と、週タブへ移るボタン。

## テスト(`time4u/test/`)

`node --test time4u/test/*.test.mjs`。`test/load-logic.mjs` はひな形どおり。少なくとも:

- `normalizeKana` / `matchesClient`: 「たな」で「田中(たなか)」が一致、「タナ」「ﾀﾅ」も一致、`name` 部分一致、空クエリ。
- `freeSlots`: 13:00〜17:00 の帯、90 分、インターバル 10 → 13:00–14:30、14:40–16:10 の 2 枠。13:00–14:30 を仮押さえすると 14:40–16:10 だけ残る(インターバルは仮押さえの後ろに空く)。ランチ(12:00–13:00)が帯 10:00–15:00 を割ると 10:00–11:30、13:00–14:30(予定の後ろにはインターバルを空けない)。面会の前にインターバルが空く。`excludeProposalId` でその提示の枠が戻る。インターバル 0。曜日・時間帯・期間フィルタ。`now` より前の枠が消える。
- `pickSpread`: 3 件が別々の日付になる。選択を残して補充する。候補が足りないときは全部。
- `buildMessage`: ヘッダ・日程・フッタの順、`{期限}` 置換、ja/en の書式。`buildReminder` の `{日時}`。
- `clientSections`: 同じクライアントが確定済みと調整中に同時に出る。期限切れフラグ。過去の並び順。`other`。
- `isExpired`: 当日は期限内、翌日から期限切れ。
- `mergeBands` / `copyWeekBands`: 重なり結合、曜日揃え、`replace` と `add`。
- `monthCells`: 42 セル、週始まり 0 と 1、月跨ぎの日付。
- `normalizeData`: 参照切れの除去、不正 `status`、配列でない値。
- `parseSlotList` と設定の補正(`defaultSlot` が `slots` にない、`dayEnd ≤ dayStart`、`eveStart ≤ pmStart`)。`timeOfDay` が設定の境界に従う。`displayName` の敬称(空文字を含む)。
- `addDays` の DST 跨ぎ(日付文字列が 1 日ずつ進む)。

## 手動確認(スマートフォン)

- IME で「たな」と打つ途中で田中が絞り込まれ、確定後も絞り込みが続く。新規登録で読みが残っている。
- クライアント → 条件モーダル → 空き枠 → 文面 → コピー → LINE に貼れる。仮押さえが週・日ビューに黄で出る。
- 回答反映で確定 → 青に変わり、残りの枠が空き枠一覧に戻る。
- 期限を過ぎても黄の枠が残り、一覧に赤系の印が出る。取消で解放される。
- 週の複写、1 日ビューのシート編集、月タブの点。
- ダーク・ライトで 4 色が見分けられる。拡縮 50〜200 でタブバーが崩れない。

## 範囲外

- Google カレンダーなど外部サービスとの同期、通知、メール/LINE の直接送信。
- 繰り返しの可能帯パターン。
- 1 日ビューでのドラッグ編集。
- 複数人・複数端末での共有(エクスポート/インポートで手動移行する)。
- 回答期限による自動解放(しない、が仕様)。
- 回答待ちの催促文面(リマインドは確定した面会に対するもののみ)。
